## Часть A. Почему так

### A1 — почему изменилось и у `a`

Переменная b копирует ссылку объекта a, поэтому изменения через b так же распространяются на объект a

### A2 — почему `3` раньше `2`

Сначала выполняется синхронный код(console.log), затем микрозадачи(Promise.then()) и затем колбэк(setTimeout()) с таймером(даже если стоит 0мс, он будет выполняться в последнюю очередь)

### A3 — почему счётчик остался нулём

В методе add используется стрелочная функция. У нее this не указывает на объект counter, поэтому при вызове counter.add()
значение counter.n не увеличивается. Чтобы это исправить, нужно использовать обычную функцию вместо стрелочной.

## Часть B. Что было не так

Четыре находки. По каждой: в чём была проблема и что вы исправили.

### Ошибка 1

**Было не так:** (удаление). В массиве id хранится как число, а здесь оно сравнивается с текстовым значением,
а в функцию removeTask() передаётся строка. Из-за строгого сравнения === нужная задача не находилась,
и удалялась последняя задача.

**Исправил:**. `const task = tasks.find((t) => t.id === Number(id));`

### Ошибка 2

**Было не так:** (сортировка) Метод sort() использовался без функции сравнения, поэтому 
задачи не сортировались.

**Исправил:** ` tasks.sort((a, b) => b.priority - a.priority);`

### Ошибка 3

**Было не так:** Было не так: Метод filter() возвращал новый массив с важными задачами, но этот результат
никуда не сохранялся, поэтому список оставался прежним

**Исправил:** `tasks = tasks.filter((task) => task.priority >= 5);`

### Ошибка 4

**Было не так:** Функция createCounter() вызывалась внутри обработчика клика, поэтому при каждом 
нажатии счётчик создавался заново и показывал 1

**Исправил:** Вынесла создание счётчика перед обработчиками нажатий.
`const countActions = createCounter();
document.querySelectorAll(".btn").forEach((btn) => {
btn.addEventListener("click", function () {
actionsEl.textContent = countActions();
});
});`
