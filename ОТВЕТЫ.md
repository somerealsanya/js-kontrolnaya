## Часть A. Почему так

### A1 — почему изменилось и у `a`
Потому что a и b - это две ссылки на один объект. В коде мы меняем значение у b, но у a тоже меняется. 
Мы же в строчке: const b = a; просто дали объекту b второе имя.

### A2 — почему `3` раньше `2`
Потому что сначала выполняется синхронный код (1 и 4 в консоли), потом уже обработчик промиса(микрозадачи), а потом уже обработчик таймера. 
Поэтому сначала 3, потом 2.
У setTimeout нулевая задержка, она не требует немедлинный вызов

### A3 — почему счётчик остался нулём
Метод add - стрелочная функция. У неё нету своего this. Она берет его из окружающего кода, а не из обьекта counter. 
Поэтому counter.add(); не меняет counter.n

## Часть B. Что было не так

Четыре находки. По каждой: в чём была проблема и что вы исправили.

### Ошибка 1

**Было не так:** Должна происходить сортировка, но массив не меняется, потому что sort вызывался без функции сравнения.

**Исправил:** Передаем в sort функцию сравнения tasks.sort((a, b) => b.priority - a.priority);

### Ошибка 2

**Было не так:** При нажатии "Удалить" удалялась последняя задача вместо выбранной. Из dataset.id приходит строка, а в массиве id хранится число.
Из-за строгого сравнения findIndex ничего не находил и возвращал -1, а splice(-1, 1) удалял последний элемент.

**Исправил:** Преобразуем id в число через Number(id) и с помощью filter оставляем все задачи, кроме выбранной
tasks = tasks.filter((task) => task.id !== Number(id));

### Ошибка 3

**Было не так:** При нажатие кнопки "Только важные" ничего не происходит. Метод filter возвращает новый массив, который никуда не сохраняется, потому что filter — немутирующий метод.

**Исправил:** tasks.filter((task) => task.priority >= 5); То есть filter проходит по всему массиву и смотрит каждую задачу, если важна кладёт её в новый массив.

### Ошибка 4

**Было не так:** Счетчик срабатывает 1 раз и не обновляется. Переменная count объявлялась внутри функции обработчика клика

**Исправил:** Выносим const countActions = createCounter(); из функции
